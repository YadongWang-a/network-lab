## Question

用户提问：路由器端口只支持 3 个吗？可不可以随连线数目变化？

现状（WF-21 遗留）：`KIND_INTERFACES.router` 硬编码 3 口（enp0s3/enp0s8/enp0s9），端口点 `PORT_POS` 三元素取模，占满后 `handleConnect` 只能弹「所有接口已连接，请先断开再连线」。

## 落点

1. 域（`src/domain/deviceFactory.ts`）：`ROUTER_BASE_PORTS = 3` / `ROUTER_MAX_PORTS = 8` / `routerInterfaceName(ordinal)`（基础 3 口径沿 legacy，追加口 enp0s10、enp0s11…）/ 私有 `createRouterInterface`（取子网池第 ordinal 个子网网关，池中无对应子网 → 无 IP 待手动配置）/ 导出 `syncRouterPorts`。
2. store（`src/state/store.ts`）：`addConnection` / `removeConnection` / `removeDevice` 三处拓扑动作后同步路由器端口；新增共用 `usedIpsIn(topology, excludeDeviceId?)` 收口「已占用 IP」口径（原 addDevice / setDhcpClient 内联循环并入）。
3. UI（`src/ui/App.tsx`）：`PORT_POS` 取模 → `portLayout(count)` 环布（左→右→顶→底 轮流坐边，同边多口沿该边均分；基础 3 口仍是 左/右/顶）；`portHandleStyle` / `portLabelStyle` / `PORT_TIP_SIDE` 三件套随偏移走。上限提示 `msg.maxPorts`（zh/en）。
4. 测试：`tests/domain/router-ports.test.ts`（6 用例）。

## Resolution（2026-09-12）

端口数 = `clamp(max(基础 3, 已连线数 + 1), …, 上限 8)`：**恒留 1 个空口供拉线**（React Flow 必须已有 Handle 才能起拖，故不能「用到才现造」），占满最后一个空口即自动追加 `enp0s10…`。收缩只回收「尾部、未连线、未配置 IP」的追加端口 —— 基础端口与手动配过 IP 的端口永不回收（用户配置不丢）。追加口在默认子网池（3 个子网）外，故无自动 IP，需抽屉/终端手动配置；UI 端口标签显示「未接线」。

验收证据：

- `tsc --noEmit` ✓；`vitest` 40/40（含新增 6 用例：基础 3 口与网关分配、占满追加 enp0s10、断开回收、上限 8 口（enp0s14 封顶）、手配 IP 不回收、删交换机回收）；`eslint .` ✓；`vite build` ✓；Playwright 4/4 ✓。
- 浏览器实测（headless 真实拖拽，非单测口径）：新建拓扑 → 拖入路由器 + 交换机 → 逐口拉线。3 口时 1/2 条线仍 3 口；第 3 条线 → 4 口（enp0s10 现）；从 enp0s10 再拉 → 5 口（enp0s11 现）；悬停线缆 × 断开 → 回落 4 口（enp0s11 回收）。
- 布局几何（实测 5 口）：enp0s3 左边 33.3% / enp0s8 右边 50% / enp0s9 顶边 50% / enp0s10 底边 50% / enp0s11 左边 66.7% —— 各口独立不重叠，底边标签让开设备名牌（截图 `.wayfinder/ui-wf25.png`，视觉复核「无重叠、可读」）。

环境补齐（附带）：`node_modules` 缺 `@playwright/test` 与 vitest 实体包、Playwright 浏览器未装，导致 `tsc` 报 5 条 e2e 缺模块错误与 `pnpm e2e` 全红 —— 已 `pnpm install` + `npx playwright install chromium` 修复，非本次改动引入。
