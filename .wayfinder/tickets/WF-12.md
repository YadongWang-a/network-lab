## Question

确立测试方案与覆盖率目标：

- 仿真引擎单测（vitest）：ARP 学习/洪泛、ICMP 回显、DHCP 四步、DNS 解析、TCP 握手、路由查表、TTL/Time-Exceeded。
- 组件测试：关键 UI（配置抽屉、画布、终端）。
- 端到端：保留/重写原 Playwright（`tests/network_lib.spec.js`、`switch.spec.js`）。

## Notes

- 引擎纯函数化（WF-3）是单测可行的前提。
- 需定义「协议行为正确」的可观测契约，避免只测源码文本。

## 交付

五项决策（grilling 逐条锁定，2026-09-08）：

1. **单测载体 = vitest，`scripts/verify-engine.ts` 退役** — 9 场景契约拆为 `tests/engine/*.test.ts`（7 文件 25 用例），共享助手 `tests/helpers/engine.ts`。`pnpm test` / `test:watch`。
2. **覆盖 = 契约清单制，不设数字门槛** — 每用例断言可观测契约（SimEvent 流 hop/dropped/notice + store 最终状态），不测源码文本；纯函数域（ipam/routing/parsers/filesystem）按边界条件覆盖。
3. **组件测试不做** — UI 靠 E2E 兜底；终端命令逻辑已被单测覆盖，测组件壳是测管道。
4. **E2E = Playwright 最小冒烟**（`playwright.config.ts` + `tests/e2e/app.spec.ts`，webServer 自动拉起 vite 5273）— 4 用例：中文 UI 加载、拖放三设备 + IPAM 上牌 + 拉线入交换机、种子拓扑演示 ping（追踪行 ×4 + 报文动画帧）、终端 `ip addr`。不复刻原版全套 spec。
5. **命令入口 = `pnpm test` / `pnpm e2e` 两条独立命令，不挂 pre-commit** — e2e 慢不进提交链；TS 门禁仍为 `tsc --noEmit`（build 内）。

实施注意（踩坑记录）：

- **App 挂载即播种演示拓扑**（`seedTopology`：PC-0/PC-1/Switch-0/Router-0/DHCP-0 全接 Switch-0），e2e 的 ping/终端用例直接复用种子拓扑（连通的 /24 段）；拖放用例先点「新建拓扑」清场。
- antd Select 下拉关闭后 DOM 仍挂载（`ant-select-dropdown-hidden`），option 定位必须加 `:not(.ant-select-dropdown-hidden)` 限定。
- `viz-dot` 动画帧是瞬态（每跳 40ms×steps + 320ms 边闪），断言须 `waitFor` 先挂、再点开始。
- 引擎单测的 store 是模块级单例，vitest 按文件隔离 module registry，文件内用 `beforeEach` 清拓扑即可并行。
- 已删：`scripts/verify-engine.ts` + 同目录 4 个一次性 probe-*.mjs。

验收（2026-09-08 实测）：`tsc --noEmit` ✓、`vitest run` 25/25 ✓（7 文件）、`playwright test` 4/4 连续两轮 ✓、`vite build` ✓、`eslint .` 0 error ✓。
