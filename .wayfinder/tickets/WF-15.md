## Question

把运行中的原型拓扑数据流（D1）从本地 `useState` 换成 `store.topology`：画布设备/连线/编辑成为 store 的投影与写入口，WF-6/7 自动配置与路由重算随之真正生效。仿真（D2）保持假数据不动，保证 M1 验收只聚焦拓扑一致性。

## Notes（接线面清单，行号已核于 2026-09-03 摸底）

替换四处：

1. **种子拓扑**：`seedNodes`（L288-294）/`seedEdges`（L296-301）→ 挂载时用 `store.addDevice`/`addConnection` 灌入（switch 先建，设备后连；与 store 校验兼容）。
2. **拖放建设备**：`onDropDevice`（L384-432）删内联 `SubnetPool` 副本 → `store.addDevice(kind, {position})`（id/标签/分配全由 store 定，顺序注意 addDevice 的 `deviceSeq` 与原型 `seq` 冲突处理）。
3. **拉线**：`onConnect`（L968）→ `store.addConnection(deviceId, ifaceId, switchId)`。**连线语义 = 交换机终端**（WF-14 决策）：目标非 switch 时拒绝并提示（文案走 i18n）。原型节点只有一个中心 source Handle（L216-242）——接线面设计点：路由器多接口时选「第一个空闲接口」（`connectedSwitchId==null`），全忙报中文错；也可先做单接口设备（PC/服务）+ 路由器三接口顺序选。
4. **编辑**：配置 Drawer `onFinish`（L1141-1146）→ `updateDevice`/`updateInterface`；IP/掩码变更后路由表自动重算（store 已内置触发）。

配套改动：

- `DeviceNodeView`（L208-265）从扁平 `DeviceData` 改接 store 真 Device：节点 data 只存 deviceId + kind（图标/名牌用），其余字段经 selector 订阅；未配置 IP 以 `ip==null` 为单事实源，'—' 仅展示层（i18n key 已存在 `device.unconfigured`）。
- 节点/边数组 = `topology` 的派生投影（`useStore` selector + 记忆化），拖拽位置变化写 `updateDevice(id,{position})`（store 对非路由键 patch 不触发重算，见 updateDevice 实现）。
- Drawer services/firewall 静态区（L1157-1181）可顺带切到真 Device 字段展示（浅读即可，深改留 WF-11/17）。
- 连线校验、报错、位置同步等新增文案进 zh/en locales（勿模块级固化，沿用 useTranslation 或 i18n.t 双模式现状）。
- **验收门**：拖放 PC/路由器/交换机→地址分配与路由表重算与 store 一致；连非交换机被拒且提示中文；断开（需要时补 removeConnection UI 入口或画布双击删边）；配置抽屉保存后画布名牌/路由表同步；9 个演示命令仍可运行（假仿真未动）；`tsc --noEmit` + `pnpm build` 绿。

## Resolution（2026-09-03）

**已实现，验收通过（浏览器实测）。**

- **投影层**：`nodes`/`edges` 改为 `store.topology` 派生（deviceMap/connections 双 selector + 记忆化），节点 `data` 只存 `{kind, deviceId}`；删除本地拓扑 state。kind 双向映射：面板 kind → store DeviceKind（apache2 归并 pc + 启 apache2 服务，WF-17 方向；annotation 暂不支持 → 面板 tile 转惰性，同 isc-* 平级）；`uiKindOf(device)` 从 Device 真身（services.apache2 启用 → www-server 图标）决定图标。
- **写回路径**：拖放 `store.addDevice`（删内联 SubnetPool 副本，池耗尽中文报错 toast）；拉线 `handleConnect` → 一端须为交换机（device↔device / switch↔switch 拒绝，i18n 提示）→ 取第一个空闲接口 `addConnection`；节点拖拽位置经 onNodesChange position → `updateDevice` 写回；RF 选中态本地回环（不落 store），节点/边删除键经 onNodesChange/onEdgesChange remove → `removeDevice`/`removeConnection`（店级清理其连线）。清除「新建拓扑」= 清空 store。
- **种子拓扑**：挂载时经 store 动作灌入 5 设备 4 连线（同一交换机 192.168.1.0/24：PC .2/.3、路由器 enp0s3 网关 .1、DHCP .4 —— WF-6 冲突检测自动顺延），旧友好名经 updateDevice 恢复（Switch-0/Router-0/DHCP-0）；StrictMode 幂等。
- **DeviceNodeView + 配置抽屉**：节点组件按 deviceId 订阅 store（删除自动消失）；名牌/主 IP 来自真 Device。抽屉改造：接口编辑器（每接口 ip/netmask，路由器含 IPv4 转发开关 + 三接口、网关编辑限终端设备）、已安装服务 Tag 表（services 真值 + dhcpPool → DHCP 服务）、**路由表只读展示（WF-7 自动计算：直连标"直连"，空态提示连线后计算）**、防火墙规则真值表（空态显示"无"）。保存经 updateDevice/updateInterface（空串 → null），IP/掩码变更触发路由重算。
- **演示命令**：buildSequence/replayHop/arpscan/dns/dhcp 全部改读 store 设备真身（主接口 IP/MAC 用真实随机 MAC，删除下标推导），http 假想公网 IP 保留注释标注（WF-17 移除）。9 命令假仿真数据流未动。
- **i18n**：新增 zh/en 各 17 键（路由表/接口/连线错误/服务标签等）；antd App 包裹启用 message。
- **验证**：`tsc --noEmit` + `pnpm build` 绿；Bun 无关（store 已在 WF-7 测）。浏览器实测（headless Chrome CDP）：种子 5 设备按 WF-6 语义自动分配（.2/.3/.1/.4）；改名保存 → 画布名牌同步；设备↔设备拉线被拒且中文提示、边数不变；路由器空闲接口（enp0s8）拉线到交换机 → 路由表自动新增 `10.0.0.0/24 直连 enp0s8`（与既有 192.168.1.0/24 并存）；节点键盘删除 → store 清理（含边）；拖放新增设备入库（位置写回验证 +75/+47、他节点不动）；Ping 演示（PC-1→PC-0）在真实 store 设备上产出 ARP+ICMP 四步序列（真实 MAC/IP）；「新建拓扑」清空至 0 节点、刷新后种子重灌。
- **遗留**：annotation 标注暂不支持拖放（域模型无此概念，WF-17/18 处理）；拖拽性能在超大拓扑下未优化（写回粒度待 WF-16 实测）；cmd 目标选择与端口 UI 细节（antd Select）未变。
