## Question

连线过程对路由器多接口完全不透明：`handleConnect` 静默取「第一个空闲接口」，用户不知道接到了哪个口、该口 IP 是什么。而 WF-7 路由按「(交换机, 子网) × 路由器接口」入网段图——**接哪个口决定哪个子网进哪段**，选错口拓扑语义完全不同，静默代选是正确性隐患。单口设备（PC/服务器等）无歧义，不受影响。

## Decision（用户选定：端口映射连接点）

- `DeviceNodeView`：路由器一接口一端口点（`PORT_POS`：enp0s3 左 / enp0s8 右 / enp0s9 顶），Handle id `p-<ifaceId>`；悬停**或任意连线拖拽中**（`useConnection().inProgress`）显示端口名 + IP，未连线端口灰字标「IP · 未接线」；已连线端口点置灰且 `pointerEvents: none`（不可再拖，但仍作边锚点）。
- 路由器移除中心/四边通用连接点，连线只能从具体端口发起；`handleConnect` 由所拖端口的 handle id（`p-` 前缀）定接口，无 `p-` 前缀（其余设备）维持「第一个空闲接口」。
- 边投影：`fromDevice` 为路由器时 `sourceHandle = p-<fromInterfaceId>`，线锚定到端口点而非节点中心。
- 路由器创建即全接口分 IP（WF-6 既有语义），故标签恒显 IP，未连线时追加「未接线」后缀（i18n `port.unconnected`，zh/en 各 +1 key）。

## 验收（2026-09-09）

- tsc strict ✓；vitest 34/34；e2e 4/4×1；build ✓。
- 浏览器实测（HMR，真 store/引擎路径）：悬停路由器显示 3 端口标签；判别性拖拽两轮——①已连 enp0s3 后拖右口 → enp0s8 落线（与 fallback 恰同，弱判别）；②清场后**先拖右口** → enp0s8 变灰、enp0s3 保持蓝（fallback 必选 enp0s3，故端口映射判定成立）；未连线端口「IP · 未接线」渲染正确；边锚定端口点。
## 增补（用户反馈·2026-09-09）


- 路由器名牌下的单一 IP 不再显示（多接口下无意义）；已连线端口点+「端口名 + IP」**常显**（不依赖悬停）。
- 未连线端口点仅悬停/连线拖拽中出现，标签改点级 antd Tooltip（`端口名 · IP · 未接线`，贴画布右缘自动内收，避免铺开裁切）；连线拖拽中三端口标签全铺开供选口。

验收增补：tsc ✓ + e2e 4/4 + 浏览器实测（不悬停仅已连线标签常显；悬停未连线点出 tooltip；拖拽中全铺开；误落交换机本体不建线）。
