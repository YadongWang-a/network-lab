## Question

设备属性抽屉当前对所有类型渲染近乎同一张表单（label + 逐接口 IP/掩码/网关 + 路由器转发开关 + 服务只读标签 + 路由表只读），仅交换机有 L2 提示。用户提出：**不同设备应可配置不同的内容**。需要决策：

1. 各设备类型（pc / router / switch / dns-server / dhcp-server / dhcp-relay-agent / apache2）各自的属性面板应包含哪些**可编辑**项？
2. 现在只读展示的域（dhcpPool、named zones、apache2 vhost、防火墙、路由表）是否升级为可编辑？编辑落 store 字段还是仍走终端配置解析器（WF-10）？
3. WF-7 路由表为拓扑自动重算——若允许手填静态路由，自动与手工如何共存（覆盖/合并/冲突策略）？
4. 网关字段（现仅终端可填）与 IPAM 自动分配的关系：手动改口后自动分配的跳过语义（WF-6）是否要扩展到网关/掩码？
5. 落点：扩展现有 Drawer（按 kind 分区渲染）还是拆分独立组件？

## Notes

- 现状代码：`src/ui/App.tsx` Drawer（~1232-1375），`initialValues` 按 kind 少量差异；服务区只读（`serviceDetailLine`）。
- store 已有字段：`ipv4Forwarding`、`dhcpPool`、`services.<name>.config`（named zones / apache2 vhosts / dhcpd range）、`firewall`（引擎未消费，WF-19 登记）、`routingTable`（WF-7 自动生成）。
- 关联：WF-6（IPAM 手动覆盖语义）、WF-7（路由自动生成）、WF-10（配置解析器落 store）、WF-17（服务引擎语义）、WF-19（firewall/NAT 引擎未消费为登记缺口）。

## Resolution（2026-09-09）

用户逐题确认：范围 = **仅按类型裁剪表单**（不动语义、只读域不升级可编辑、不添新领域字段）；区块矩阵 = **裁空区块**。落地：

- 路由器：label + 转发开关 + 接口（IP/掩码，无网关行）+ 路由表。
- 交换机：label + L2 提示（接口/服务/路由表全不渲染）。
- 终端设备（PC/DNS/DHCP/中继，含 apache2 归并体）：label + 接口（IP/掩码/网关）+ 服务区块。
- 服务区块仅存在已启用服务时渲染（去掉「（无）」占位整块）；路由表仅路由器渲染；防火墙区块整删（引擎不消费、恒渲染「无」，WF-19 已登记缺口），连带 i18n 孤儿 `drawer.firewall`/`fw.protocol`/`fw.action`/`svc.iptables`（zh/en 各 -4）与 `SERVICE_KEYS.iptables` 清除。
- 落点：扩展现有 Drawer 条件渲染（`enabledServiceEntries` 助手抽为模块级函数），不拆组件。

验收：tsc strict ✓；vitest 34/34；e2e 4/4；zh/en key 对齐 210；浏览器实测四类抽屉内容与矩阵一致。
